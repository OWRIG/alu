# Agent 接口设计

- 日期：2026-08-09
- 性质：工程与产品方向 memo，不代表已实现行为

## 出发点

"Agent 友好"不等于在应用里塞一个聊天框。第一性原理拆解：agent 要能**读到真相**（项目、参数、BOM、规则结论）、**安全地写**（经校验、可预览、可撤销）、**拿到结构化反馈**（错误码、变更摘要）、**学会怎么用**（自描述与工作流指引）。这四件事全部落在已有的纯函数领域内核上，缺的只是一个 headless 传输层和一份教学层。

## 决策

1. **内核一份，入口两个。** UI 命令与 headless CLI 都走同一个 `applyCommand` 与规则评估，没有旁路。同一初始 designHash 与命令批必须得到相同最终 designHash；保存元数据不同导致 fileHash 不同不算领域结果漂移。
2. **传输层 = headless CLI（P4）。** 直接读写 `.alu` 文件：校验、参数求值、dry-run/apply 批量命令、导出 BOM/规则、目录搜索。输出机器可读 JSON、退出码稳定。不开网络端口、不加新攻击面；Claude Code 等终端 agent 立即可用。
3. **教学层 = 配套 Agent Skill。** SKILL.md 随产品仓库版本化维护，内容：何时用、读 → dry-run → apply 的工作流、参数优先、错误码与规则结论解读、不要绕过 CLI 手改 `.alu`。skill 中的示例命令进入冒烟测试，schema 引用构建产物，不手写两份。
4. **不做 MCP server。** CLI + skill 已覆盖终端 agent 的全部工作流；MCP 额外带来服务进程、工具注册和生命周期维护，当前没有"只支持 MCP、无法执行本地 CLI"的宿主需求。
5. **不预建内置聊天界面。** agent host 生态已成熟，应用内对话框是重复的劣质轮子。粘贴命令 JSON 的导入口保留为调试兜底。真实需求出现前不做模型 API 接入、密钥管理和流式 UI。
6. **协议形状第一天定型（P1），传输层后置（P4）。** 加字段便宜、改形状贵，因此 MVP 命令信封就包含：
   - `commands: DomainCommand[]` 批量原子——任一失败整批不落地；
   - 新增类命令的实体 ID 由调用方提供，同批后续命令可引用，agent 可离线组合多步计划；
   - `commandId` 请求关联 + `expectedProjectRevision` / `expectedDesignHash` 乐观并发；当前不承诺跨进程持久幂等；
   - 结构化拒绝：稳定错误码 + JSON Pointer + 相关实体 + 修复方向；
   - dry-run 返回结构化变更摘要（实体增删改、受影响参数、规则增减、BOM 差异）。
7. **读写对称。** 项目快照、参数求值、BOM、规则结论、目录搜索都是纯函数投影，读结果一律携带 `projectRevision + designHash`，agent 检测过期而不是盲写。响应丢失后重试若遇 revision 冲突，先重新读取并比较 designHash，不静默重复应用。
8. **"agent 改文件、人看结果"的廉价桥。** 应用检测已打开工程的 `.alu` 被外部修改时提示重载。live attach（连接运行中应用、实时投影）推迟到演示/结对成为真实需求。
9. **工程文件读写模块保持 Electron 无关。** 纯 Node 实现，main 与 CLI 复用同一份原子写与校验逻辑。

## 被否决

- MCP server：见决策 4；为不存在的宿主需求维护一个服务进程不划算。
- 应用内置聊天面板与模型 API 管理：在 agent host 生态成熟的前提下是重复建设。
- 一步到位的 live socket 协议：headless CLI + 文件重载已覆盖当前全部 agent 工作流。
- 为 agent 单独设计一套"简化 API"：读写都必须走领域命令与投影，两套 API 必然漂移。

## 复议触发

- 出现只支持 MCP、无法执行本地 CLI 的重要宿主 → 以 CLI 内核补一层薄 MCP 适配，不另写业务逻辑。
- 需要在应用里实时观看 agent 建模（演示、结对、教学）→ live attach。
- 工程规模让全量快照读取成为 token 瓶颈 → 增加按实体/区域的选择性读命令与修订间 diff 命令。
- 第三方要求网络接口 → 评估 HTTP 局域网口，默认仍然关闭。
