# 第一性原理复审

- 日期：2026-08-09
- 性质：工程与产品方向 memo；修订同日方案基线，不代表已实现行为

## 触发

基线文档存在一个核心断裂：README 与黄金样例把"空间约束 → 尺寸链"当作产品灵魂，但工程文档没有定义参数、公式、绑定的任何机制，MVP changeset 也没有任何参数 case。fixture 断言了一个没有任何阶段负责实现的能力；照原计划做出来的 P1 只是"手动摆盒子"，恰恰不包含产品的差异化核心。

## 调整

1. **参数尺寸链升级为 P1 核心子系统。** 输入参数 + 线性组合派生参数 + 实体字段绑定；单向纯函数求值加环检测；`SetParameters` 一步命令同步绑定。黄金样例从 P1 起就是可执行的纯函数测试。
2. **公式形式刻意收窄为线性组合。** 已知尺寸链全部是加减法；不做公式 DSL、表达式解析、双向约束求解。真实需求出现后按版本化 AST 扩展。
3. **`.alu` 初始容器从 ZIP 改为单一规范化 JSON。** P1 没有二进制资产：内嵌目录与 BOM 快照本就是 JSON，预览图改为 userData 派生缓存。读取端未来可嗅探 `{` 与 `PK`，但 ZIP 使用独立 `containerVersion`，不与 ProjectDocument 的 `formatVersion` 共用“v2”。
4. **加工信息单一来源。** 型材实体只保留端部切型（平切/斜切）；孔、攻丝、沉孔要么由连接 definition 派生，要么是显式人工加工记录。删除 `endA`/`endB` 双写位，避免与"加工由连接派生"自相矛盾。
5. **取消独立 catalogLock。** `PartRef` 恒带精确 revision——引用即锁定；`embeddedParts` 既是流通载体也是锁定证据。一套机制，不留两处真相。
6. **P1 交互降级，核心前移。** P1 用参数面板 + 属性编辑 + 只读 3D 投影交付完整闭环；拖拽/吸附/gizmo 移到 P2 与端点吸附一起做。先交付差异化的领域核心，后做视图交互。
7. **撤销明确为结构共享快照。** `applyCommand` 是结构共享纯函数，只重建变更路径，100 步历史是 100 个引用；内存 ≈ 累计变更量，不预装 Immer。
8. **补 `ProjectContext`。** 地面材质、移动性、人身承载、载荷等场景事实此前在 schema 中无处安放，而 B/E 类规则全依赖它们。字段允许显式 `unknown`，`unknown` 视为待确认而非安全。
9. **数值量化。** 持久化 mm 值在命令边界量化到 0.01 mm，canonical JSON 固定数字格式，支撑 `C-bom-recompute-stable` 的哈希稳定。
10. **坐标映射固定。** 领域 Z 向上 ↔ three.js 默认 Y 向上的换算只存在于 viewport 适配层，three 坐标不得写回领域状态。
11. **P1 schema 不冻结未来占位。** v1 只包含 P1 已实现的型材语义；连接、加工、板材、脚轮和人工 BOM 在对应 changeset 中定义强类型并升级文档版本。
12. **哈希与幂等拆开。** designHash 排除时间和派生缓存，fileHash 表示完整保存字节；`commandId` 不宣称跨进程持久幂等，expected revision 防止静默重复写入。

## 被否决

- 字符串公式 DSL / 任意表达式求值：解析器与兼容成本先于需求出现。
- 双向约束求解器：那是通用 CAD 的路，明确出圈。
- 初始 ZIP 容器：为不存在的二进制资产支付攻击面与多条目一致性成本。

## 复议触发

- 出现线性组合覆盖不了的真实模板公式 → 扩展版本化公式 AST。
- 工程需要携带照片、图纸等二进制资产 → 启用带独立 `containerVersion` 的 ZIP 容器。
- 参数/绑定规模或求值耗时成为实测瓶颈 → 增量求值。
