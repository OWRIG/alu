# 铝 ALU 路线图

## 当前状态

- 阶段：方案基线
- 当前目标：确认 MVP 行为契约，随后建立 Electron 纵向切片
- 当前 changeset：`changes/2026-08-09-bootstrap-mvp.md`（草案，未批准、未实现）

## 范围

### 做

- 工业铝型材骨架、连接节点、加工和配套零件建模
- 面板、脚轮等与型材结构直接相关的附件
- 可复核 BOM、切割表、加工表和装配提示
- 自定义零件目录与工程包流通
- 中文优先、离线优先、AI 友好的桌面编辑器

### 不做

- 通用实体 CAD、自由曲面、机械装配全功能或 FEA
- 自动声称结构安全、额定承载或厂家可加工
- 第一阶段的云协作、账号、商城、下单和支付
- 允许工程文件执行 JavaScript 的插件系统

## 阶段

1. **P0 工程基线**：Electron 安全边界、目录、Zod schema、质量门禁。
2. **P1 纵向切片**：新增/编辑型材、3D 投影、`.alu` 保存重开、型材切割 BOM。
3. **P2 节点与完整 BOM**：连接件、紧固件、加工、板材、脚轮、装配顺序。
4. **P3 自定义目录与流通**：自定义零件、工程内嵌目录、导入冲突处理、CSV/JSON 导出。
5. **P4 AI 指令与效率工具**：命令预览、批量生成、规则解释、模板和参数化家具向导。
6. **P5 分发**：macOS/Windows 打包、签名、升级与发布回归。

## 已决策

| 日期 | 决策 | 理由 |
| --- | --- | --- |
| 2026-08-09 | 产品名定为“铝 / ALU” | 用户明确要求只保留最直接的单字名称，不加功能后缀 |
| 2026-08-09 | Electron + electron-vite | 统一 Chromium 环境，Keel 已验证该组合的桌面工程可行性 |
| 2026-08-09 | 单包、三进程、框架无关 domain | 保留安全边界，避免复制 Keel 的 monorepo 复杂度 |
| 2026-08-09 | 显式 IPC + Zod，暂不引入 oRPC | MVP API 小，先保持行为直接可查 |
| 2026-08-09 | Three.js 只做视图投影 | 工程数据、BOM 和 AI 命令不依赖渲染对象 |
| 2026-08-09 | `.alu` 是版本化 ZIP 工程包 | 同时携带工程、引用目录、BOM 快照和预览图 |
| 2026-08-09 | BOM 分派生、人工项、调整三层 | 重算不覆盖用户意图，来源可追溯 |
| 2026-08-09 | 规则分硬错误与经验警告 | 经验不能伪装成厂家认证或结构计算 |

## 开放问题

1. 第一批正式型材与连接件数据来自通用目录还是嘉立创目录快照。
2. P1 只显示简化矩形截面，还是同时引入真实 T 槽轮廓。
3. 首个 BOM 交换格式除 CSV/JSON 外，是否立即支持 XLSX。
4. macOS 与 Windows 的首发优先级及签名主体。
5. 哪些结构规则能获得厂家公开数据支持，哪些只能保留为经验警告。
