# joints-and-machining

> 状态：已完成。

## Why

工程现在只有一堆互不相干的型材。用户看不到**两根型材之间靠什么连起来**，也看不到**因此要在哪里打孔**——而这两件事决定了能不能真的做出来。

后果具体而严重：

- 料单只有型材切料，连接件和紧固件完全缺失，下料买回来发现装不上。
- 「哪根要攻丝、哪根要打通孔、孔距端面多少」全靠人脑记，最容易出错的一步没有任何记录。
- 下单完成度条的「连接件」与「加工」两项恒为「尚未建模」。
- `structure.mobile-side-sway` 规则的理由是「模型不含连接拓扑」——这条限制正是本单要解除的。

选择连接方式**直接改变要不要打孔**：角码用 T 型螺母卡进槽里，一个孔都不用打；内置连接件要在侧面开工艺孔、端面攻丝。这个差别现在完全无法表达。

## 第一性原理

- 连接是显式实体，不是从型材相对位置猜出来的。位置关系不等于连接关系。
- 加工是连接的**结果**，不是独立输入。选定连接方式后孔位随之确定，不允许两处双写。
- 孔位由几何推导：型材端面位置、截面尺寸和连接定义共同决定，不编造。
- 孔径来自公开标准（ISO 螺纹底孔与通孔），标注为 `standard` 证据；具体厂商连接件 SKU 保持待确认，不猜。
- 中性连接类型不绑定任何厂商体系；将来映射到具体 SKU 是新增映射，不是重写模型。
- 3D 的职责是让人看清孔在哪、连接件在哪，而不是好看。

## Delta

### ADDED `project.joint-entities`

- `.alu` 新增可选顶级字段 `joints`，强类型记录连接节点。`formatVersion` 保持 `1`：该字段可选，全部既有 P1 工程无需迁移即可打开。
- 每个节点记录：稳定 ID、连接类型、主构件与其端面（`end-a` / `end-b`）、被连接构件、螺栓规格与数量。
- 节点进入 `computeDesignHash`，连接变化会产生新的设计哈希。
- 引用不存在的型材、主被构件相同、同一端面重复连接均被拒绝。

### ADDED `domain.connection-catalog`

三种中性连接类型，覆盖铝型材最常见做法：

| 类型               | 是否需要加工 | 派生加工                             |
| ------------------ | ------------ | ------------------------------------ |
| `corner-bracket`   | **否**       | 无。T 型螺母卡入两侧型材槽           |
| `hidden-connector` | 是           | 主构件端面攻丝；被连构件侧面开工艺孔 |
| `butt-screw`       | 是           | 主构件端面攻丝；被连构件侧面开通孔   |

- 孔径取自 ISO 标准：`M5→Ø4.2 底孔 / Ø5.5 通孔`，`M6→Ø5.0 / Ø6.6`，`M8→Ø6.8 / Ø9.0`。
- 攻丝深度取螺栓公称直径的 2.5 倍，向上取整到 mm。
- 每条派生加工携带 `standard` 证据引用，置信度 `high`；连接件本身的厂商 SKU 保持 `null` 并标为待确认。

### ADDED `domain.derived-machining`

- 新增纯函数 `deriveMachining(project)`，从 `joints` 推导全部加工记录。
- 每条记录包含：所属型材、面（端面或四个侧面之一）、加工种类（攻丝 / 通孔）、直径、深度、沿轴向距端面距离、横向偏移、来源节点 ID。
- 侧面孔位沿主构件截面中心对称分布；双螺栓时按被连构件截面高度的 1/4 与 3/4 分布。
- 结果是纯函数产物，不写回型材字段。

### ADDED `bom.hardware-lines`

- 料单新增「连接件与紧固件」区，与型材切料分开显示。
- 每个节点派生：1 个连接件 + N 个螺栓 + N 个 T 型螺母（仅 `corner-bracket` 与 `hidden-connector`）。
- 按类型与规格聚合，数量可核对；`bomHash` 覆盖硬件行。
- 每行显式标注厂商 SKU 待确认，不填充推测型号。

### ADDED `editor.machining-list`

- 「料单」页新增「加工」区，按型材分组列出全部孔位：面、种类、直径、深度、距端面距离。
- 每条加工可追溯到来源节点；选中型材时只显示该型材的加工。

### ADDED `editor.joint-editor`

- 右侧新增「连接」页：列出全部节点，可新增、选择、删除。
- 新建节点时选择主构件与端面、被连构件、连接类型、螺栓规格与数量；界面直接显示该选择会派生几个孔。
- 选中节点时 3D 高亮对应位置。

### ADDED `viewport.machining-overlay`

- 3D 中在每个孔位画出标记：攻丝为实心，通孔为空心，颜色区分。
- 连接件在节点位置以半透明体块显示。
- 视口新增三个开关：显示/隐藏加工标记、显示/隐藏连接件、只看选中型材（隔离）。

### ADDED `viewport.dimension-and-section`

- 选中型材时显示其切长标注与两端坐标。
- 新增沿 X/Y/Z 的剖切滑块，用于看清框架内部与孔位。

### CHANGED `rule.mobile-side-sway`

- 工程已有连接节点时，规则理由改为陈述连接拓扑已建模但刚度未计算，不再声称「模型不含连接拓扑」。
- 触发条件与严重度不变。

### CHANGED `editor.order-readiness`

- 「连接件」环节在工程至少有一个节点、且全部型材端面都被连接覆盖时就绪。
- 「加工」环节在全部派生加工都有明确直径与深度时就绪；无需加工的工程（全部为 `corner-bracket`）同样算就绪。

## Not in this change

- 不做人工加工记录（只做连接派生）；`sourceJointId` 字段已为其预留位置但不开放写入。
- 不做板材、脚轮建模，完成度条仍停在 3/5。
- 不做拖拽与吸附交互；节点通过属性编辑创建。
- 不做具体厂商连接件 SKU、槽口兼容性校验与槽段占用冲突检查。
- 不做真实 T 槽轮廓；型材仍是矩形包络，孔位画在包络表面。
- 不声称任何连接强度、扭矩或承载值。

## Cases

- `C-joint-explicit-not-inferred` 两根型材相交但没有节点时，不产生任何连接或加工。
- `C-joint-validates-refs` 引用不存在的型材、自连接、同端面重复连接均被拒绝且工程不变。
- `C-bracket-needs-no-machining` `corner-bracket` 节点派生零条加工记录，但仍派生连接件与紧固件。
- `C-hidden-connector-machining` `hidden-connector` 节点在主构件端面派生攻丝、在被连构件侧面派生工艺孔，数量等于螺栓数。
- `C-machining-diameters-from-standard` M5/M6/M8 的底孔与通孔直径与 ISO 标准一致，且携带 `standard` 证据。
- `C-machining-single-source` 加工只出现在派生结果中，型材实体上没有任何孔位字段。
- `C-machining-position-from-geometry` 孔位随型材长度、截面与端面选择变化，不是常量。
- `C-hardware-bom-aggregation` 相同类型与规格的连接件与紧固件按数量聚合，`bomHash` 随之变化。
- `C-hardware-sku-unconfirmed` 硬件行的厂商 SKU 为待确认，不出现推测型号。
- `C-joint-design-hash` 增删节点改变 `designHash`，保存重开后节点与派生加工完全一致。
- `C-joint-removed-with-member` 删除型材时，引用它的节点一并移除，不留悬空引用。
- `C-readiness-connectors` 全部端面被连接覆盖后「连接件」环节就绪。

## 实施说明

- `JointSchema` 放在 `src/domain/project/schema.ts`，与其他文档实体并列；`src/domain/joints/schema.ts` 只保留派生类型。最初把文档 schema 放在 `joints/` 会与 `project/schema.ts` 形成循环导入，导致 `EntityIdSchema` 在构造时为 undefined。
- 孔位按真实直径绘制，但真实 M8 孔在两米长的框架上只有几个像素。因此每个标记额外画一个保持恒定视觉大小的定位环：真实尺寸不被篡改，位置仍然找得到。
- 内置示例新增 8 处连接：顶框四角用内置连接件（各 4 个孔），四根立柱用角码（不用打孔）。这让「选连接方式直接决定要不要打孔」在打开应用的第一屏就能看到。
