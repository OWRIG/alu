# interface-language

> 状态：已完成。

## Why

界面文案有四类问题，合计影响 319 条中文条目里的约 80 条。

**一、同一个概念有三到五种叫法。** 标签页写「构件」，区块条写「10 根型材」，领域层叫 `profile`，store 里叫 `entity`。左栏标题写「设定约束」，内容全是「参数」，计数写「13 项输入」。右下角写「5 项复核」，标签页写「检查 5」。用户没法建立稳定词汇表。

**二、自造术语被当成通用词。** `boundaryKind` 的七个中文标签——「骨架外包」「结构内净」「动态余量」「障碍外沿」——是四字自造词，用户第一次见，且对「障碍物最外沿宽是多少」零帮助。

**三、把系统内部状态当用户文案。** 「3D、definition 与切料清单现在引用同一快照」把英文标识符和内部实现词混进中文；「继续修改参数时，手工值不会被静默覆盖」讲的是系统的实现承诺而非用户该做什么；状态栏常驻「版本 0」与「设计 1b85680a」是给 agent 做幂等校验的内部值。

**四、免责声明重复到失效。** 同一件事在四处出现：顶栏「概念模型 · 不可下单」、视口水印「概念模型」、料单页「不含连接件、加工、板材和脚轮，不可直接下单」、选型页 81 字长句，合计 127 字。重复到第四次用户会整类屏蔽，连同真正的阻断项一起忽略——**过度免责降低而不是提高安全性**。

同类的还有信息重复：型材数量在标签页、区块条和状态栏各出现一次；单位 `mm` 在视口标题、视口水印、每个数值后缀和状态栏各出现一次，而 `meta.units` 在 schema 里写死为 `mm` 且不可切换。

左栏顶部的「01 · 步骤 1 · 设定约束」承诺了一条线性流程，但右侧是四个平行标签页，没有步骤 2。

## 第一性原理

- 一个概念一个词。词汇表先定，再写文案。
- 界面按用户认得的东西命名，不按系统怎么实现命名；稳定 ID、hash、revision 属于调试信息，不属于常驻界面。
- 同一个事实在界面上只说一次，说在它最该出现的地方。
- 结构性装置（编号、步骤、分组）只在内容真的具有那个结构时使用。
- 披露边界的正确形式是「离目标还差什么」，不是重复「你不能做什么」；同一条边界只说一次，并且可展开看细节。
- 空状态给的是下一步动作，不是缺失清单。

## Delta

### ADDED `editor.order-readiness`

- 新增纯函数 `evaluateOrderReadiness(project)`，返回通往可下单料单的五个环节及其就绪状态：型材、连接件、加工、板材、脚轮。
- 「型材」在工程至少有一根型材、且每根型材的规格都带厂家 SKU 时就绪；概念包络不算就绪。
- 连接件、加工、板材、脚轮在对应建模能力落地前恒为未就绪，理由为「尚未建模」。
- 状态栏显示为一条「离下单还差」进度条与 `n/5` 计数，可展开查看每一项的状态与原因。

### REMOVED `editor.repeated-disclaimers`

- 删除顶栏「概念模型 · 不可下单」标记、视口「概念模型」水印与料单页顶部的免责条。
- `sizing.boundary.body` 由 81 字压缩为一句结论，未覆盖项移入可展开的细节区，原文完整保留。
- 领域层 `HANDOFF_BOUNDARIES` 与交付单内容不变；本变更只改界面呈现，不减少任何披露内容。

### CHANGED `editor.terminology`

统一五组术语，中英文同步：

| 概念     | 原有叫法                             | 定为                         |
| -------- | ------------------------------------ | ---------------------------- |
| 型材实例 | 构件 / 型材 / 根 / entity / profile  | 型材（Members）              |
| 料单     | 下料 / 切料分组 / 型材下料清单 / BOM | 料单（Cut list），长度为切长 |
| 尺寸参数 | 约束 / 参数 / 输入 / 尺寸 / 尺寸链   | 尺寸，分实测与推导两类       |
| 规则结果 | 检查 / 复核 / 检查结果 / findings    | 检查（Checks）               |
| 型材规格 | definition / 概念包络 / 快照         | 型材规格（Profile）          |

### CHANGED `editor.left-panel-header`

- 删除「01」序号与「步骤 1」提示；左栏标题由「设定约束」改为「尺寸」。
- 计数由「13 项输入」改为「13 项」，与标题不重复。

### CHANGED `editor.status-bar`

- 移除常驻的「版本 {n}」「设计 {hash}」与「毫米」。
- 保留保存状态与检查计数，新增下单完成度。
- 型材数量不再在状态栏重复，只保留在「型材」标签页。

### CHANGED `editor.viewport-chrome`

- 视口标题由「透视视图 · 毫米模型 · 世界坐标」简化为「透视视图」。
- 移除「概念模型」与「单位 mm · Z 轴向上」水印，保留平嵌板说明。

### CHANGED `editor.boundary-labels`

- `boundaryKind` 的中文标签由自造四字词改为普通类别名：障碍外沿 → 障碍物、动态余量 → 预留间隙、结构内净 → 内部净空、骨架外包 → 骨架外形、结构 → 其他。
- 这些标签现在是分组标题（每组出现一次），不再逐行重复。

### CHANGED `editor.empty-states`

- 空状态文案改为可执行的下一步动作，不再罗列系统缺什么。
- 参数行副标题只显示稳定 ID，不再重复分组标签。

### CHANGED `editor.rule-copy`

- 规则理由改为陈述用户处境与后果，不再描述系统内部承诺。
- 选型理由由单句三层定语改为结论加逐条约束核对。

## Not in this change

- 不改三栏布局、栏宽、可折叠性与行高。
- 不改任何领域语义、规则触发条件、严重度、`blocks` 或计算结果。
- 不改 `.alu` 文档 schema、稳定 ID、rule ID 或命令名称。
- 不改交付单内容与 `HANDOFF_BOUNDARIES`；披露只在界面上去重，不在产物中删减。
- 不做 3D 尺寸标注、剖切与隔离显示。
- 不修 `keyDimensionIds` 仍硬编码内置示例四个参数 ID 的问题，该项留待后续 changeset。

## Cases

- `C-terminology-single-word` 界面中「构件」「下料」「切料」「复核」「设定约束」不再出现；同一概念只用词汇表中的一个词。
- `C-no-duplicate-counts` 型材数量只在标签页出现一次，检查数量只在标签页与状态栏各一次。
- `C-no-internal-values-in-chrome` 状态栏不显示 revision 与 design hash。
- `C-single-disclosure-point` 顶栏、视口与料单页不再各自重复不可下单提示；边界只在完成度条与选型页各出现一次。
- `C-readiness-derived-not-hardcoded` 内置示例应用厂家 SKU 后「型材」环节就绪，未应用时不就绪。
- `C-readiness-counts-five-steps` 完成度条恒为五个环节，未建模的四项给出「尚未建模」理由。
- `C-no-step-numbering` 左栏不再出现「01」与「步骤 1」。
- `C-locale-parity` 中英文条目一一对应，无孤立键。
