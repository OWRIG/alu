# i18n-and-task-flow

> 状态：已实现，已验证。

## Why

当前界面把中英文固定文案直接写在各组件里，同一视图同时出现“尺寸参数 / Dimension System / Inputs / Derived / BOM”等标签。语言没有单一来源，信息层级也沿着代码数据结构平铺，没有围绕用户完成设计的顺序组织。

## 第一性原理

- 用户的目标不是浏览参数表，而是得到一个可检查、可保存的结构方案。
- 最短闭环是：设定约束 → 查看模型与关键结果 → 检查构件、下料和风险 → 保存。
- 一个界面会话只使用一种系统语言。品牌、单位、坐标轴、文件名、稳定 ID 和用户输入的数据不做伪翻译。
- 默认语言是简体中文；语言选择器是唯一允许同时显示语言自称的位置。

## Delta

### ADDED `editor.locale-system`

- 用一个有类型的语言包管理 renderer 固定文案，不引入第三方 i18n 依赖。
- 支持 `zh-CN` 与 `en-US` 完整切换，选择持久化到本机并同步 `document.lang`。
- 内置样例的项目名、参数名、构件用途、型材概念名和规则解释按稳定 ID 本地化；用户自定义内容保持原文。
- 工程通知使用结构化消息，领域错误在英文界面不回退为中文系统提示。

### CHANGED `editor.task-oriented-layout`

- 左侧从“输入/派生参数平铺”改为“空间边界 / 框架包络 / 桌板装配”三个任务组。
- 关键结果常驻，完整计算结果折叠，减少低优先级数字占用。
- 中央 3D 继续作为主工作区；右侧只保留构件、下料、检查三个结果入口。
- 去掉装饰性的中英双标签，用信息层级、字号和间距表达结构。

## Not in this change

- 不翻译用户自己创建或编辑的项目内容。
- 不引入在线翻译、语言自动检测或更多语言。
- 不改变工程文件 schema、尺寸链、几何、BOM 聚合或规则判定结果。
- 不重做 SpaceX 风格的基础色彩和三栏桌面布局。

## Cases

- `C-i18n-default-zh` 首次启动使用简体中文，界面不再显示随机英文栏目标签。
- `C-i18n-switch-persist` 切换英文后所有系统栏目与内置样例文案统一为英文，重载后保持选择，可切回中文。
- `C-i18n-domain-copy` 通知、领域错误与规则解释跟随语言；稳定 ID、单位和用户内容保持原样。
- `C-task-oriented-parameters` 输入按三个设计任务分组，关键结果常驻，完整计算结果可展开。
